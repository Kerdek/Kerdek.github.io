Lambda Calculus for Formal Proof

You've written functional programs. You might have written a lambda calculus program—perhaps a clever fixed-point combinator, a church numeral arithmetic function, square a list manipulation. Your code works. You've tested it. Can you prove it has the desired properties?

We won't add type annotations to our existing lambda calculus programs. Instead, our programs will become types—parts of logical propositions. Then, we'll construct terms which prove the properties.

Why This Matters

This approach transforms informal reasoning about programs into formal, mechanically-checkable proofs. Instead of arguing that "square produces non_negative outputs," we construct a mathematical object to constitute the proof.

Untyped Programs

Consider a simple program in the untyped lambda calculus:

square = \x.mul x x

This is the square of a number. In the untyped world, we can apply square to anything: numbers, functions, even square itself. The calculus doesn't stop us. We might informally claim "square a is non_negative for all a which are real," but this remains an informal assertion. This is a property of our program, stated in natural language, living outside the formal system.

The question is: can we bring these claims inside the formal system? Can we can manipulate them with the same rigor as our programs?

Propositions about Programs

We include the program in a proposition. Propositions are a richer language. Propositions are built from arrows, and quantifiers, and parts of programs. We can put a program in a proposition. A program that returns a proposition is called a predicate. We augment the syntax with:

  • Arrows ->: Implication. P -> Q says "P implies Q."
  • Universal quantifiers \/: For all. \/x.P says "For all x, P."

These are features of propositions which state properties. Our programs remain untyped, but they occur in propositions, and those say things about them.

\/x.real x -> non_negative (square x) is a proposition. The program square is part of it. Read this as: "For all x, if x is a real number, then x2 is non-negative."

real and non_negative are predicates. The arrow -> connects the antecedent to the consequent. The quantifier \/x ranges over all possible inputs.

Terms as Proofs

A type might be inhabited by a term (e.g. 2 inhabits Int). A proposition is a type which is proved by its inhabitants, proofs.

To prove \/x.real x -> non_negative (square x), we need a term of this type. This term would look like:

/\x. \p : real x. mul_non_negative x x p p \. iff_refl (non_negative x)

The type abstraction /\x introduces the type variable x. The abstraction \p : real x introduces a proof of type real x—we're assuming the premise. The body proves non_negative (square x).

mul_non_negative is a proof that a real product is non_negative when non_negative matches on coefficients:

theorem mul_non_negative : \/a b.real a -> real b -> iff (non_negative a) (non_negative b) -> non_negative (mul a b)

The proof term has computational meaning. It takes evidence that real x, applies reasoning about multiplication, and produces evidence that the result is non_negative.

Rules of Inference

These are the four possible ways to construct proofs. Each of them uses the context Γ to track types.

Conditional Proof (-> Introduction)

Logical form: Assuming premise P, Q. So, P → Q.

Proof term: Lambda abstraction which proves P -> Q:

\i : P.E

This is a conditional proof on premise i : P of proof E : Q.

Judgment rule:

i must not be bound in Γ, P must be closed in Γ, and E must prove Q in Γ, i : P (proof i of P appended to Γ).

i ∉ Γ

Γ ⊢ P

Γ, i : P ⊢ E : Q

Γ ⊢ \i : P.E : P -> Q

Mechanics: \a : t. discharges the antecedent t -> in the goal and introduces a premise a : t in the context. The body uses these like function parameters.

Example:

theorem syllogism : \/a b.a -> (a -> b) -> b := /\a b. \pa : a. \pab : a -> b. pab pa.

The body pab pa proves b for arbitrary propositions a and b and premises pa : a and pab : a -> b.

Modus Ponens (-> Elimination)

Logical form: P → Q and P. So, Q.

Proof term: Function application which proves Q:

E F

This is a modus ponens through proof E : P -> Q from proof F : P.

Judgment rule:

F must prove P, and E must prove P -> Q in Γ.

Γ ⊢ F : P

Γ ⊢ E : P -> Q

Γ ⊢ E F : Q

Mechanics: When pab : a -> b and pa : a, pab pa proves b. This applies the proof to specific premises.

Generalization (\/ Introduction)

Logical form: Given arbitrary i, P. So, ∀i.P.

Proof term: Type abstraction which proves \/i.P:

/\i.E

This is a generalization over given i of proof E : P.

Judgment rule:

i must not be bound in Γ, and E must prove P[j := i] in Γ, i.

i ∉ Γ

Γ, i ⊢ E : P[j := i]

Γ ⊢ /\i.E : \/j.P

Mechanics: /\a. discharges the universal quantifier \/a. in the goal and introduces an arbitrary a in the context. The body uses these like type parameters.

Example:

theorem implication_reflexive : \/a.a -> a := /\a. \pa : a. pa.

The body \pa : a.pa proves a -> a for arbitrary a.

Specialization (\/ Elimination)

Logical form: ∀i.P. So, P[i := T] for arbitrary T.

Proof term: Type application which proves P[i := T].

E Q

This is a specialization of proof E : P for proposition Q.

Judgment rule:

Q must be closed in Γ, and E must prove \/i.P in Γ.

Γ ⊢ Q

Γ ⊢ E : \/i.P

Γ ⊢ E Q : P[i := Q]

Mechanics: When a : \/i.a -> i, a t proves a -> t. This instantiates the proof for specific propositions.

Examples:

theorem false_of_false : false -> false := implication_reflexive false

Summary

This calculus makes proof judgment mechanical: writing a proof is writing a well-typed program. Type soundness guarantees logical soundness. If a proof type-checks, it represents a valid proof of its proposition.
