Lambda Calculus for Formal Verification

The Verification Gap

If you've written a functional program, you probably experienced a familiar tension. You write a function, test it on inputs, watch it behave correctly. Yet, some doubt remains. Does it always work? For every possible input? You may say "the result is never negative". That claim transcends the test suite. It is not about a handful of test cases. It's about all possible inputs—a universal property. Yet, your evidence remains circumstantial.

This gap between testing and certainty drives programmers toward various solutions: more tests, property-based testing, careful code review, defensive programming, and sophisticated typing systems. These are valuable practices, but they share a fundamental limitation: they don't establish universal properties. Those live in comments, documentation, and discussions, which are not checked by the machine.

Testing the Program

Alonzo Church's untyped lambda calculus is a simple model of computation. In the untyped lambda calculus, square = ⅂a.mul a a is a program.

define square := ⅂a.mul a a.

Note: The program has no type annotations. In untyped lambda calculus, programs are not constrained by types.

You might claim square always returns a non-negative result for real number inputs. How do you gain confidence in this claim? You might test: non_negative (square 2), non_negative (square -3), non_negative (square 0). Each test increases your confidence, but you can never test all real numbers. You might reason informally: "Multiplying two numbers of the same sign never gives a negative result, and squaring uses the same number twice...". This reasoning is sound, but it is prose.

From Testing to Proving

What if your claims about the program could be expressed with the same precision as the program? What if a computer could check that they are correct? This is the promise of the Curry-Howard correspondence, the connection between programs and proofs that underlies much of modern proof assistants and dependently-typed programming languages.

Testing can show the presence of bugs. Proof, by contrast, can show their absence. It closes the gap between specification and implementation.

Other approaches constrain the program with types. We will constrain what counts as proof. That is, the program will be part of a proposition:

theorem Real-non_negative-square : ∀a.Real a → non_negative (square a).

"For all a, if a is a real number, then a2 is non-negative."

The proposition does not add typing to the program. It is a type that expresses the property. There is a term of that type, which is a proof. We write programs, make propositions about those programs, and construct proofs for those propositions.

Propositions about Programs

Propositions are a richer language built from arrows, quantifiers, and parts of programs. We can put a program in a proposition. A program that returns a proposition is a predicate. We augment the syntax with:

  • Arrows →: Implication. a → b says "a implies b."
  • Quantifiers ∀: For all. ∀a.b says "For all a, b."

Propositions which state properties. Our programs remain untyped, but they occur in propositions, and those say things about them.

∀a.Real a → non_negative (square a) is a proposition. The program square is part of it. Real and non_negative are predicates. The arrow → connects the antecedent to the consequent. The quantifier ∀a. ranges over all possible inputs.

Proofs

A type might be inhabited by a term (e.g. 2 inhabits Int). A proposition is a type which is proved by its inhabitants, proofs.

To prove ∀a.Real a → non_negative (square a), we need a proof (a term) of this proposition (this type). Such a proof is:

proof Real-non_negative-square := Ʌa. ⅂pa : Real a. Real-non_negative-mul (a) (a) pa pa [ Eq-refl (sign a)].

The universal proof Ʌa. is a type abstraction which introduces the type variable a. The conditional proof ⅂pa : Real a. is an abstraction which introduces proof pa of Real a, the antecedent. The body shows non_negative (square a), the consequent.

This proof accepts proof that a is Real and returns proof that square a is non_negative.

Real-non_negative-mul is a proof that mul a b is non_negative when a and b are Real and have equal sign. Its proposition is:

theorem Real-non_negative-mul : ∀a b. Real a → Real b → Eq (sign a) (sign b) → non_negative (mul a b).

Eq-refl takes care of Eq (sign a) (sign a):

theorem Eq-refl : ∀a. Eq a a.

The proof has computational meaning. It takes proof of Real a, applies reasoning about multiplication, and produces proof of non_negative (square a).

The system is untyped only with respect to the programs being discussed. The propositions form a typing system which makes universal claims about those untyped programs, and the typing rules correspond to logic. That's what closes the verification gap: not typing your program, but typing your argument about the program.

The Curry-Howard Correspondence

This correspondence establishes a precise mapping between domains that might seem unrelated:

  • Logic: propositions, proofs, and inference rules
  • Programs: types, terms, and typing judgments

By Curry-Howard, each logical construct is a programming construct:

A logical proposition is a type. A proof of that proposition is a term inhabiting that type. To prove a proposition is to provide a well-typed term. Logical implication (a → b) is a function type a → b. Universal quantification (∀a.b) is a polymorphic type ∀a.b. Rules of logical inference are typing rules. A type checker is a proof checker. Type soundness is logical soundness.

Summary

This calculus makes proof judgment mechanical: a proof is a well-typed term. A valid proof shows its proposition.

Appendices

Meaningful Judgmental Equalities

Propositions may be related by judgmental equalities. Certain judgmental equalities are meaningless because they lead these inference rules to contradiction. For example, in the theory of unintepreted functions, Russell's classic paradox, Y not shows the contradiction.

-- statement of contradiction define False := ∀a. a. -- `Not a` means `a` implies `False` define Not := ⅂a. a → False. -- fixed point combinator define Y := ⅂f. (⅂a.f (a a)) (⅂a.f (a a)). -- Russell's theorem theorem Russell : Y Not := ⅂p: Y Not. p p. -- inconsistency theorem Contradiction : False := Russell Russell.

There are numerous accounts of meaningful judgmental equalities. Some examples include:

  • Normalizing Systems
  • Set Theories
  • Type Theories

Judgment Rules

These are the four possible ways to construct proofs. Each of them uses the context Γ to track types.

Generalization (∀ Formation)

Logical form: Given arbitrary a, p a. So, ∀a.p a.

Proof term: Type abstraction which shows ∀a.p a:

Ʌb.E

This is a generalization over arbitrary b of proof E : p b.

Judgment rule: b must not be bound, and E must show p b in b ⊢ (proposition b appended to ⊢).

⊬ b

b ⊢ E : p b

⊢ Ʌb.E : ∀a.p a

Mechanics: Ʌb. discharges the universal quantifier ∀a. in the goal and introduces an arbitrary b in the context. The body uses these like type parameters.

Specialization (∀ Usage)

Logical form: ∀a.p a. So, p b for some b.

Proof term: Type application which shows p b.

E (b)

This is a specialization of proof E : p b for proposition b.

Judgment rule: b must be closed, and E must show ∀a.p a.

⊢ b

⊢ E : ∀a.p a

⊢ E (b) : p b

Mechanics: Specialization instantiates the generalization proof for specific propositions.

Assumption (→ Formation)

Logical form: Assuming a, b. So, a → b.

Proof term: Lambda abstraction which shows a → b:

⅂P : a.E

This is an assumption on premise P : a of proof E : b.

Judgment rule: P must not be bound, a must be closed, and E must show b in P : a ⊢.

⊬ P

⊢ a

P : a ⊢ E : b

⊢ ⅂P : a.E : a → b

Mechanics: ⅂pa : t. discharges the antecedent t → in the goal and introduces a premise pa : t in the context. The body uses these like function parameters.

Syllogy (→ Usage)

Logical form: a → b, and a. So, b.

Proof term: Function application which shows b:

E P

This is a syllogy through proof E : a → b from proof P : a.

Judgment rule: P must show a, and E must show a → b.

⊢ P : a

⊢ E : a → b

⊢ E P : b

Mechanics: When pab : a → b and pa : a, pab pa shows b. This applies the proof to specific premises.

Examples

theorem Imp-refl : ∀a. a → a := Ʌa. ⅂pa : a. pa.

The body ⅂pa : a.pa shows a → a for arbitrary a.

theorem False-of-False : False → False := ImpRefl (False).

Imp-refl (False) shows False → False.

theorem Imp-syl : ∀a b. a → (a → b) → b := Ʌa b. ⅂pa : a. ⅂pab : a → b. pab pa.

The body pab pa shows b for arbitrary propositions a and b and premises pa : a and pab : a → b.
